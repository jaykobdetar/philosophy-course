## 4. Teaching, feedback and validation rules

Each released packet contains a guiding question, exact source/context, task, expected output, feedback criteria and a next step. Practice permits appropriate scaffolding; independent checks explicitly restrict task-specific help. The tutor receives actual sources and may record uncertainty. These design choices implement the alignment principle described by Carnegie Mellon: teaching/practice and assessment must address the same intended skill. [E1]

Use method-sensitive criteria and labelled, source-checked examples, plus an explicit feedback-challenge route. Calibrate the tutor on a small known-case set rather than certify it from eloquence or agreement with other agents. Use a baseline, fresh transfer sample and delayed check in the learner pilot. This synthesis’s particular AI test set is a proposed local quality check, not a validated external benchmark. [E2]

“Unseen” means not previously rehearsed with this learner in the recorded scope; it does not mean secure examination. Record prior exposure and permitted assistance. A separate folder/session is useful separation, not secrecy. Keep administration small and include a restart-after-break procedure.
