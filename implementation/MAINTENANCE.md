# Maintaining the current course

1. Edit the affected `current/` page or `instruction/` packet. For a reading change, update the work, edition, asset or assignment record in `data/course.json`; retain a stable ID if the entity is unchanged. Pin the actual edition, passage boundary, language, link and rights/quality status. Preserve the source DOCX and conversion baseline.
2. Record the decision in `implementation/DECISIONS.md`: date, PC ID, course/module, source, task, assessment, workload consequence, verification and unresolved limits. Reopen a previously scoped task if its source, rubric, structure or tooling changed.
3. Adjust `data/workload.json` using focused learner time for reading, context, exercise, feedback, revision and assessment. Name any displaced hours. Count shared work once and add needs-based bridges only on routes that take them. Do not publish a revised full-route total until every required addition is scoped.
4. Run `python3 scripts/build_views.py` and `python3 scripts/check_course.py` from the repository root. The latter checks generated-view freshness, local links, IDs, prerequisites and directly compatible option routes, baseline hours, substantive DOCX-conversion preservation, collection checksums, capstone milestones and private-path rules. Fix every error before release. The original plan's intentional two-space Markdown line endings are kept unchanged.
5. Before the affected module opens, test external reading links and visible passage markers in the chosen edition. A failed link calls for a legitimate equivalent acquisition route and a new locator check; it does not authorize substitution with a summary. Inspect copyright, edition and quotation quality separately.
6. Keep learner responses in `learner/` or another private location outside Git. If distributing a teaching package, first inspect `data/distribution.json`, then run `python3 scripts/package_course.py` and inspect the result. The allowlist is a containment rule, not a copyright clearance or public-release approval.

The [status record](STATUS.md) distinguishes packet readiness, curriculum specification and actual learner validation. A private Git repository can contain historical reading bundles; neither that fact nor an ignore rule grants public redistribution permission. Public visibility, history rewriting, mass publication, paid review and outreach require a separate decision.
