# Maintaining the current course

1. Edit the affected `current/` page or `instruction/` packet. For a reading change, update the work, edition, asset or assignment record in `data/course.json`; retain a stable ID if the entity is unchanged. Pin the actual edition, passage boundary, language, link and rights/quality status. Preserve the source DOCX and conversion baseline.
2. Record the decision in `implementation/DECISIONS.md`: date, PC ID, course/module, source, task, assessment, workload consequence, verification and unresolved limits. Reopen a previously scoped task if its source, rubric, structure or tooling changed.
3. Update the affected course's `authoring.json` using focused learner time for reading, context, exercise, feedback, revision and assessment. Preserve the source module hours; additions separately name gross, displaced and net hours. Count shared work once and add needs-based bridges only on routes that take them. `scripts/build_workload.py` computes the route and stopping-milestone totals; `data/workload.json` retains the earlier proposal history separately.
4. Obtain independent content review after substantive changes. Check actual assigned sources when accessible; distinguish primary passage inspection from alternate translations, bibliographic metadata and abstracts. Compare new independent forms against the whole coached corpus: changed names alone do not establish a fresh task. Save the review scope and remaining limits in `implementation/reviews/`. Refresh the affected record in `data/authoring-reviews.json` only after acceptance. It records the exact file list, individual SHA-256 hashes and digest of their canonical sorted JSON; unrelated later edits invalidate acceptance until rechecked.
5. Generate in order: `python3 scripts/build_instruction_views.py`, `python3 scripts/build_workload.py`, then `python3 scripts/build_views.py`. Run `python3 scripts/check_course.py` from the repository root. It checks all fourteen course manifests and twenty tracks, exact accepted inventories, generated-view freshness, local links, IDs, prerequisites, directly compatible option routes, authored budgets, substantive DOCX-conversion preservation, 214 collection checksums, capstone milestones and private-path rules. Run any affected course's checker as documented in its README. Fix errors before a reviewed checkpoint. The original plan's intentional two-space Markdown line endings are kept unchanged.
6. Before the affected module opens, test external reading links and visible passage markers in the chosen edition. A failed link calls for a legitimate equivalent acquisition route and a new locator check; it does not authorize substitution with a summary. Inspect copyright, edition and quotation quality separately.
7. Keep learner responses in `learner/` or another private location outside Git. For a local teaching package, inspect `data/distribution.json`, run `python3 scripts/package_course.py`, and inspect its inventory. Source archives, reading collections and private records are deliberately omitted; links back to omitted repository material require the private checkout. Python caches are excluded. The allowlist is a containment rule, not copyright clearance or public-release approval.

The [status record](STATUS.md) distinguishes packet readiness, curriculum specification and actual learner validation. A private Git repository can contain historical reading bundles; neither that fact nor an ignore rule grants public redistribution permission. Public visibility, history rewriting, mass publication, paid review and outreach require a separate decision.
